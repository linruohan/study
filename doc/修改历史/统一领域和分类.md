# 统一为父类/子类知识树（删除「领域」概念）

## Context

当前模型是三层：`知识分类 knowledge_categories`（可嵌套，不能挂知识）→ `知识领域 knowledge_domains`（挂知识，不可嵌套）→ `知识 knowledge_concepts`。用户要求：**没有领域的区分，所有都是父类/子类**——知识直接挂在可嵌套的分类（子类）上，客户端与服务端彻底统一。已确认走「客户端+服务端彻底统一」路线，含数据库迁移（现有领域自动并成对应父类下的子类，id 尽量保留，现有计划/档案无需手动迁移）。

## 服务端（server/）

### 1. 迁移 `server/db/016_unify_category_tree.sql`（新文件，编号接现有 015）

用临时映射表处理 id 撞名（种子数据里根分类 `life` 与领域 `life` 同名）：

1. 建临时表：每条领域 → `new_id`（若领域 id 与现有分类 id 冲突则用 `'cat_' || d.id`，否则沿用原 id），并带上 parent_id/name/glyph/color/sort_order。
2. `INSERT INTO knowledge_categories (...) SELECT ... FROM 映射表`（question/ancient/modern 置空串）。
3. `knowledge_concepts` 加 `category_id text REFERENCES knowledge_categories(id)`，按映射表回填（= 原 domain_id → new_id），`SET NOT NULL`，`DROP COLUMN domain_id`。
4. `DROP TABLE knowledge_domains`（连同其索引）。
5. sage 贡献表的 `domain_id` 列保留（不透明字符串，客户端继续传此键，值变为分类 id）。

### 2. 仓储/类型/路由

- `src/knowledge/knowledge.types.ts`：删除 `DomainDto`；`CategoryDto` 增加嵌套 `concepts: ConceptDto[]`（原领域挂概念的方式平移到分类）。
- `src/knowledge/knowledge.repository.ts`：
  - bundle 组装：一次查出全部分类（含 parent_id），按分类聚合查 concepts（`category_id`，按 depth/sort_order），删掉领域查询与 `createDomain`；
  - `createConcept` 改收 `categoryId`（校验分类存在）。
- `src/knowledge/knowledge.routes.ts`：删除 `POST /api/knowledge/domains`；`POST /api/knowledge/concepts` 的 zod schema 字段 `domainId` → `categoryId`；分类创建/改名路由不变。
- `src/me`、`src/knowledge/sage.*`：不动（用户数据 JSON 对服务端不透明；sage 贡献字段仍叫 `domainId`）。

## 客户端（app/）

### 3. 模型层

- `lib/knowledge/domain.dart`：**删除** `LearningDomain`。
- `lib/knowledge/taxonomy.dart`：`ScholarCategory` 增加字段 `concepts`、方法 `conceptsFor(band)`（原 `LearningDomain.conceptsFor` 逻辑：availableIn 过滤 + depth/id 排序）、`hasContent(band)`、`displayNameFor(band)`（幼儿档 language/math/life → 识文/识数/识物 的改名逻辑平移过来）。
- `lib/knowledge/concept.dart`：`domainId` → `categoryId`（解析时由所属分类注入）。
- `lib/knowledge/knowledge_graph.dart`：只持有 `categories`；`childrenOf/rootCategories/categoryById/unlocked` 不变；`domainsFor→categoriesWithContent`、`directDomainsInCategory/allDomainsInCategory/domainsUnderCategory` 删除（知识直接取 `category.conceptsFor`）；`domainById→categoryById`；`nextStep(focusCategoryId)`、`readyCount(category,...)`。
- `lib/knowledge/knowledge_catalog.dart`：解析新 bundle（分类内嵌 concepts），去掉 domains。

### 4. 持久化兼容

- `lib/plan/study_plan.dart`、`lib/archive/learning_record.dart`、`lib/profile/study_profile.dart`：字段 `domainId` → `categoryId`；**fromJson 兼容旧键**（`categoryId ?? json['domainId']`），toJson 写新键；旧本地数据/服务端用户数据无需迁移，值不变（旧领域 id 经 DB 迁移后仍指向同一个分类）。
