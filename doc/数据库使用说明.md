# 数据库使用说明

素材服务的数据分两处存放：

| 存放位置 | 内容 | 本地实现 |
| --- | --- | --- |
| PostgreSQL | 素材元数据、纯文本正文 | WSL2 Arch 内的 `postgresql.service` |
| 对象存储（S3 协议） | 图片 / 音频 / 视频文件本体 | WSL2 Arch 内的 `seaweedfs.service` |

数据库里**不存二进制**，只存对象存储的 `bucket + object_key`；
反过来，对象存储里也不存标题、分类这类描述信息。两边靠 `assets` 表串起来。

> 选型说明：最初计划用 Docker + MinIO，但本机 Docker Desktop 安装器无法在非交互会话中完成安装，
> MinIO 官方二进制下载也不可用，因此改为在已有的 WSL2 Arch 里直接安装。
> 对外仍是标准 S3 协议，将来换回 MinIO 只需要改 `.env` 里的地址和凭证。


## 二、表结构

### assets：素材表

图片、音频、视频、文本四类资源共用一张表，用 `kind` 区分。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | uuid | 主键，默认 `gen_random_uuid()` |
| `kind` | text | `image` / `audio` / `video` / `text` |
| `title` | text | 显示标题，必填 |
| `mime_type` | text | 如 `image/png`、`text/plain` |
| `body` | text | **仅文本**资源使用，存正文 |
| `bucket` | text | **仅媒体**资源使用，对象存储桶名 |
| `object_key` | text | **仅媒体**资源使用，对象在桶内的路径 |
| `size_bytes` | bigint | 字节数，非负 |
| `sha256` | text | 内容摘要，64 位十六进制，用于去重/校验 |
| `width` / `height` | integer | 图片尺寸，预留给后续探测任务，可为空 |
| `duration_ms` | integer | 音视频时长，预留给后续转码任务，可为空 |
| `metadata` | jsonb | 自定义元数据，默认 `{}` |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间，由触发器自动维护 |

### 两条关键约束

**1. 存储位置互斥**（`assets_storage_check`）

```sql
(kind = 'text'  AND body IS NOT NULL AND object_key IS NULL AND bucket IS NULL)
OR
(kind <> 'text' AND body IS NULL     AND object_key IS NOT NULL AND bucket IS NOT NULL)
```

这条约束保证：
- 文本资源不会有对象存储残留；
- 媒体资源不会把二进制塞进数据库。

写数据时如果违反，会直接报 `23514` 错误，属于刻意设计的保护。

**2. 对象路径唯一**（`assets_object_key_uidx`）

`(bucket, object_key)` 在 `object_key` 非空时唯一，避免两个记录指向同一个文件。

### 索引

| 索引 | 用途 |
| --- | --- |
| `assets_created_idx` | 按时间倒序翻页 |
| `assets_kind_created_idx` | 按 `kind` 过滤后按时间翻页 |
| `assets_metadata_gin_idx` | `metadata` 的 GIN 索引，支持 JSON 条件查询 |
| `assets_object_key_uidx` | 对象路径唯一 |

按 `metadata` 查询示例：

```sql
select id, title from assets where metadata @> '{"source": "smoke"}';
```

### 知识库表

知识本身也放在 PostgreSQL 里，与素材分开。层级是「九类 → 领域 → 原子概念 → 分龄呈现 → 三档知识点」。

| 表 | 说明 |
| --- | --- |
| `knowledge_age_bands` | 七档年龄段字典，含学习方式与是否显示学科名 |
| `knowledge_degrees` | 入门、熟悉、精通三档字典 |
| `knowledge_categories` | 九类分类法，含古今对应、问句、符号和颜色 |
| `knowledge_domains` | 学习领域，归属某个类别 |
| `knowledge_concepts` | 原子概念，同一概念跨年龄段只建一个节点 |
| `knowledge_concept_prerequisites` | 概念的前置依赖 |
| `knowledge_variants` | 同一概念在各年龄段的呈现：做什么、我能、提问、参考回应、说明 |
| `knowledge_variant_points` | 入门 / 熟悉 / 精通三档的具体知识点 |

几个约定：

- 业务 id 直接作为接口字段返回，客户端按 id 解析，不再维护一份本地知识；
- 颜色存 `#RRGGBB`，不存 Flutter 的 ARGB 整数；
- 没有写入的年龄段，就是该概念不在这一档出现；
- 知识点默认由呈现字段展开（入门 = topic + doing，熟悉 = check + answer，精通 = praise + note），规则见 `008_knowledge_points.sql`。

排查用查询：

```sql
select d.name, count(c.id) as concepts
  from knowledge_domains d
  left join knowledge_concepts c on c.domain_id = d.id
 group by d.name, d.sort_order
 order by d.sort_order;

select concept_id, age_band_id, count(*) as points
  from knowledge_variant_points
 group by concept_id, age_band_id;
```

新增或修改知识时，改对应的 seed 迁移并执行；应用端不再保存知识副本，
启动时通过 `GET /api/knowledge` 读取。已经执行过的迁移文件不要改内容，按编号新开文件。

### 用户数据表

设备维度保存学习设置、计划和学习档案，外键都指向知识表，避免写入不存在的知识点。

| 表 | 说明 |
| --- | --- |
| `devices` | 设备登记，`id` 是客户端生成的 UUID，记录首次与最近访问时间 |
| `study_profiles` | 每台设备一条：当前年龄档 `age_band_id` 与关注领域 `focus_domain_id` |
| `study_plans` | 学习计划，领域级与知识级共用，主键是 `(device_id, id)` |
| `learning_records` | 学习档案：练习、监护人观察和小测，主键是 `(device_id, id)` |

约定：

- 设备 ID 由应用端生成（UUID v4），首次写入时由接口自动登记到 `devices`；
- 计划与记录的 `id` 由客户端生成，只在同一设备内唯一；
- 引用了不存在的概念、领域或年龄档时，接口返回 `400 unknown_reference`；
- 保存是整份替换：同一事务内删除该设备旧数据再写入，避免半份状态。

常用查询：

```sql
select count(*) from devices;
select * from study_profiles limit 10;
select device_id, count(*) from learning_records group by device_id;
```

### 其他表

| 表 | 说明 |
| --- | --- |
| `schema_migrations` | 记录已执行过的迁移文件名与时间，由迁移脚本自动维护 |
| `knowledge_sages` | 智者名：设备 id → 创建者名，提交知识时显示 |
| `knowledge_contributions` | 知识贡献：提交即审批（status 直接写 approved），记录知识或知识点的来源 |

### 触发器

`assets_set_updated_at`：每次 `UPDATE` 前把 `updated_at` 设为 `now()`，
所以业务代码不需要手写这个字段。

## 三、迁移机制

SQL 文件放在 [server/db](../server/db)，按文件名排序执行：

```
server/db/
  001_schema.sql                  -- 建扩展、建素材表、建索引、建触发器
  002_seed.sql                    -- 两条示例文本（固定 UUID，重复执行不会插重）
  003_knowledge_schema.sql        -- 知识库建表
  004_knowledge_seed_base.sql     -- 年龄段、学习程度、九类分类
  005_knowledge_seed_language.sql -- 语领域
  006_knowledge_seed_math.sql     -- 数领域
  007_knowledge_seed_life.sql     -- 生活与安全领域
  008_knowledge_points.sql        -- 按呈现字段展开三档知识点
  009_user_data.sql               -- 设备、学习设置、计划、学习档案
```

执行：

```powershell
cd server
npm run db:migrate
```

脚本行为（见 [src/scripts/migrate.ts](../server/src/scripts/migrate.ts)）：

1. 自动创建 `schema_migrations` 表；
2. 读取 `db` 下所有 `.sql`，按文件名升序；
3. 已记录在 `schema_migrations` 里的文件会**跳过**；
4. 每个文件单独开事务，失败回滚，不会留下半成品。

### 新增一次迁移

1. 在 `server/db` 新建文件，编号递增，例如 `003_add_tags.sql`；
2. 内容写成**幂等**的（`CREATE TABLE IF NOT EXISTS`、`ADD COLUMN IF NOT EXISTS` 等）；
3. 执行 `npm run db:migrate`。

> 已经执行过的文件不要再改内容——`schema_migrations` 只记文件名，改内容不会重跑。
> 需要调整已有结构时，新开一个编号文件。

## 四、常用命令

在 `server` 目录下执行：

| 命令 | 作用 |
| --- | --- |
| `npm run db:status` | 查看 PostgreSQL 与对象存储是否在运行 |
| `npm run db:up` | 启动两者（`systemctl start postgresql seaweedfs`） |
| `npm run db:down` | 停止两者 |
| `npm run db:migrate` | 执行未跑过的迁移 |
| `npm run dev` | 启动 API 服务（默认 `http://127.0.0.1:3000`） |

查看服务日志：

```powershell
wsl -d Arch -u root -- journalctl -u postgresql -n 50 --no-pager
wsl -d Arch -u root -- journalctl -u seaweedfs -n 50 --no-pager
```

两个服务都已 `systemctl enable`，WSL 启动时会自动拉起。

## 五、接口与数据库的对应关系

完整链路是：上传 → 写对象存储 → 写 `assets` 表。

| 接口 | 对数据库的影响 |
| --- | --- |
| `POST /api/assets/text` | 插入一条 `kind = 'text'`，`body` 存正文 |
| `POST /api/assets` | 先上传对象，再插入一条媒体记录；**入库失败会删除已上传的对象** |
| `GET /api/assets?kind=&limit=&offset=` | 只读，列表不返回 `body` |
| `GET /api/assets/:id` | 只读，文本会带 `body` |
| `GET /api/assets/:id/content` | 文本回正文；媒体 302 到预签名地址 |
| `DELETE /api/assets/:id` | 先删对象存储，再删记录 |
| `GET /api/knowledge` | 一次返回年龄段、程度、九类、领域、概念与分龄内容，只读 |
| `GET /api/devices/:deviceId/data` | 读取该设备的设置、计划和记录 |
| `PUT /api/devices/:deviceId/data` | 整份替换该设备的数据，写入前自动登记设备 |

对象与知识的读取接口都带 `Cache-Control: no-store`，避免拿到过期结构。

对象的路径规则：`<kind>/<年>/<月>/<uuid><扩展名>`，
例如 `image/2026/11/02921c28-f75f-438e-ac74-ce9733faf6f6.png`。

文本资源不产生对象，`bucket` 与 `object_key` 为空。

### 应用端只保留框架

按「所有数据都放数据库」的约定，Flutter 应用不再内置知识、计划或档案：

| 应用端保留 | 说明 |
| --- | --- |
| 设备 ID | 首次启动生成 UUID，存 `device_id.txt`，用于区分数据库里的用户数据 |
| 最近一次缓存 | `study_cache.json` 存上次成功拉取的整份数据，断网时兜底 |
| 界面与交互 | 知识目录、计划、档案都从 `/api/knowledge` 与设备数据接口读取 |

启动流程：

1. 读设备 ID；
2. 若缓存里有未同步的修改，先 `PUT` 推回服务端；
3. 并行请求知识库与设备数据；
4. 请求失败但有缓存时用缓存启动，并标记为离线；两者都没有才显示加载失败。

因此删掉缓存文件不会丢业务数据，下一次联网会重新拉取。

## 六、备份与恢复

### 备份

```powershell
wsl -d Arch -u root -- bash -lc "runuser -u postgres -- pg_dump -Fc study" > study.dump
```

### 恢复

```powershell
wsl -d Arch -u root -- bash -lc "runuser -u postgres -- pg_restore -d study --clean --if-exists" < study.dump
```

对象存储的文件本体需要单独备份，数据目录在 WSL 内的 `/var/lib/seaweedfs`。

## 七、常见问题

### 1. Windows 连不上 5432 / 9000

先确认 WSL 里的服务活着：

```powershell
npm run db:status
```

若显示 `inactive`，执行 `npm run db:up`。
WSL 的 localhost 转发由 Windows 自动维护，两个服务都监听在 `0.0.0.0`，正常无需额外配置。

### 2. 重启电脑后服务没起来

WSL 实例在无进程时会被自动关闭，下次访问时再启动。
`postgresql` 与 `seaweedfs` 都设了开机自启，WSL 一拉起它们就会恢复；
如果仍然异常，执行一次 `npm run db:up`。

### 3. 需要重建整个数据库

```powershell
wsl -d Arch -u root -- runuser -u postgres -- psql -c "DROP DATABASE IF EXISTS study;"
wsl -d Arch -u root -- runuser -u postgres -- psql -c "CREATE DATABASE study OWNER study;"
cd server
npm run db:migrate
```

### 4. 换了密码

三处要同步：

1. WSL 内改数据库密码：`ALTER ROLE study PASSWORD '新密码';`
2. `server/.env` 的 `DATABASE_URL`
3. `server/scripts/wsl-pg-setup.sh` 里的默认密码（重装环境时用）

### 5. 迁移报 `relation already exists`

说明该文件的变更已经手工执行过，但没被记录。
确认表结构无误后，手动补一条记录即可：

```sql
insert into schema_migrations (filename) values ('003_xxx.sql');
```

### 6. 预签名地址返回 403 SignatureDoesNotMatch

通常是 S3 客户端与服务端的校验策略不一致。
本项目已在 [src/storage.ts](../server/src/storage.ts) 里关闭 flexible checksum 协商
（`requestChecksumCalculation` / `responseChecksumValidation` 设为 `WHEN_REQUIRED`），
如果更换存储实现后再次出现，优先检查这两项。

## 八、首次搭建环境

如果不小心删掉了 WSL 里的服务，或换了新机器，按顺序执行：

```powershell
# 1. 装包（需要联网）
wsl -d Arch -u root -- pacman -Syu --noconfirm
wsl -d Arch -u root -- pacman -S --noconfirm --needed postgresql

# 2. 初始化数据目录（只需一次）
wsl -d Arch -u root -- bash -lc "runuser -u postgres -- initdb -D /var/lib/postgres/data --locale=C.UTF-8 --encoding=UTF8"

# 3. 配置监听、建库建角色、启动服务
wsl -d Arch -u root -- bash /mnt/d/codehub/study/server/scripts/wsl-pg-setup.sh

# 4. 安装对象存储服务（二进制已随脚本下载完成时跳过第一步）
wsl -d Arch -u root -- bash /mnt/d/codehub/study/server/scripts/wsl-storage-setup.sh

# 5. 建表并写入示例数据
cd server
npm run db:migrate
```

两个脚本都是幂等的，重复执行不会破坏已有数据。
