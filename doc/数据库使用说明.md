# 数据库使用说明

素材服务的数据分两处存放,**全部用 Docker 部署**(见 [server/docker-compose.yml](../server/docker-compose.yml)):

| 存放位置 | 内容 | 本地实现 |
| --- | --- | --- |
| PostgreSQL | 素材元数据、纯文本正文、知识库、用户数据 | Docker 容器 `study-postgres`(postgres:16-alpine) |
| 对象存储(S3 协议) | 图片 / 音频 / 视频文件本体 | Docker 容器 `study-storage`(SeaweedFS) |

数据库里**不存二进制**,只存对象存储的 `bucket + object_key`;
反过来,对象存储里也不存标题、分类这类描述信息。两边靠 `assets` 表串起来。

> 选型说明:依赖服务统一走 Docker,不再使用 WSL。对象存储采用 SeaweedFS(S3 协议兼容):
> MinIO 官方已停止维护,社区可自行通过替代方案继续使用,本项目选用 SeaweedFS 作为替代。
> S3 协议通用,如需换回其他实现只改 compose 镜像与 `.env` 里的地址和凭证。

## 二、表结构

### assets:素材表

图片、音频、视频、文本四类资源共用一张表,用 `kind` 区分。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | uuid | 主键,默认 `gen_random_uuid()` |
| `kind` | text | `image` / `audio` / `video` / `text` |
| `title` | text | 显示标题,必填 |
| `mime_type` | text | 如 `image/png`、`text/plain` |
| `body` | text | **仅文本**资源使用,存正文 |
| `bucket` | text | **仅媒体**资源使用,对象存储桶名 |
| `object_key` | text | **仅媒体**资源使用,对象在桶内的路径 |
| `size_bytes` | bigint | 字节数,非负 |
| `sha256` | text | 内容摘要,64 位十六进制,用于去重/校验 |
| `width` / `height` | integer | 图片尺寸,预留,可为空 |
| `duration_ms` | integer | 音视频时长,预留,可为空 |
| `metadata` | jsonb | 自定义元数据,默认 `{}` |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间,由触发器自动维护 |

两条关键约束:

1. **存储位置互斥**(`assets_storage_check`):文本只有 `body`,媒体只有 `bucket+object_key`,违反报 `23514`;
2. **对象路径唯一**(`assets_object_key_uidx`):`(bucket, object_key)` 非空时唯一。

### 知识库表

层级是「父类/子类(可嵌套)→ 概念 → 分龄呈现 → 三档知识点 → 章节」,互动数据(评论/纠错/积分)挂在知识点上。
016 迁移已**取消"领域"层**:原领域平移为所属分类下的子类,`knowledge_domains` 表已删除。

| 表 | 说明 |
| --- | --- |
| `knowledge_age_bands` | 七档年龄段字典(蒙学…硕士),含学习方式与是否显示学科名 |
| `knowledge_degrees` | 学习程度字典(018 后四档:入门/熟练/精通/创造;familiar 中文口径由「熟悉」改「熟练」) |
| `knowledge_categories` | 分类树:`parent_id` 为空表示九大基类,非空表示子类型(可多级嵌套),含古今对应、问句、符号和颜色 |
| `knowledge_concepts` | 原子概念,`category_id` 指向分类(不再有 domain_id) |
| `knowledge_concept_prerequisites` | 概念的前置依赖 |
| `knowledge_variants` | 同一概念在各年龄段的呈现:做什么、我能、提问、参考回应、说明 |
| `knowledge_variant_points` | 四档的具体知识点;`cognitive_level` 为认知层级(remember/understand/apply/analyze/evaluate/create,默认 remember) |
| `knowledge_variant_point_chapters` | 知识点章节:按 `(concept, age_band, degree, point_position, chapter_position)` 定位,每个章节是最基础的知识单元 |
| `knowledge_point_comments` | 知识点评论,挂在知识点上,带 `device_id` |
| `knowledge_point_corrections` | 知识点纠错:`status` 为 pending/approved/rejected,含 `suggested_text`、`reviewer_device_id`、`points_awarded` |
| `knowledge_point_credits` | 积分流水:审核通过等场景发放,可追溯到 `correction_id` |

几个约定:

- 业务 id 直接作为接口字段返回,客户端按 id 解析,不维护本地知识副本;
- 颜色存 `#RRGGBB`,不存 Flutter 的 ARGB 整数;
- 没有写入的年龄段,就是该概念不在这一档出现;
- 知识点默认由呈现字段展开(入门 = topic + doing,熟练 = check + answer,精通 = praise + note),规则见 `008_knowledge_points.sql`;整包接口同时返回 `pointLevels`(与 points 按位置一一对应的认知层级)。

排查用查询:

```sql
select p.name as parent, c.name, count(k.id) as concepts
  from knowledge_categories c
  left join knowledge_categories p on p.id = c.parent_id
  left join knowledge_concepts k on k.category_id = c.id
 group by p.name, c.name, c.sort_order
 order by c.sort_order;

select concept_id, age_band_id, count(*) as points
  from knowledge_variant_points
 group by concept_id, age_band_id;
```

新增或修改知识时,改对应的 seed 迁移并执行;应用端不再保存知识副本,
启动时通过 `GET /api/knowledge` 读取。已经执行过的迁移文件不要改内容,按编号新开文件。

### 用户数据表

设备维度保存学习设置、计划和学习档案,外键都指向知识表,避免写入不存在的知识点。

| 表 | 说明 |
| --- | --- |
| `devices` | 设备登记,`id` 是客户端生成的 UUID,记录首次与最近访问时间 |
| `study_profiles` | 每台设备一条:当前年龄档 `age_band_id` 与关注分类 `focus_category_id`(026 前列名沿用 `focus_domain_id`,存的一直是分类 id) |
| `study_plans` | 学习计划,分类级与知识级共用,主键是 `(device_id, id)` |
| `learning_records` | 学习档案:练习、监护人观察和小测,主键是 `(device_id, id)` |

约定:

- 设备 ID 由应用端生成(UUID v4),首次写入时由接口自动登记到 `devices`;
- 计划与记录的 `id` 由客户端生成,只在同一设备内唯一;
- 引用了不存在的概念、分类或年龄档时,接口返回 `400 unknown_reference`;
- 保存是整份替换:同一事务内删除该设备旧数据再写入,避免半份状态。

### 其他表

| 表 | 说明 |
| --- | --- |
| `schema_migrations` | 记录已执行过的迁移文件名与时间,由迁移脚本自动维护 |
| `knowledge_sages` | 智者名:设备 id → 创建者名,提交知识时显示 |
| `knowledge_contributions` | 知识贡献:提交即审批(status 直接写 approved),010 预留 status 列供将来人工复核 |
| `users` | 用户账号:用户名唯一、scrypt 密码哈希、角色 user/admin;内置 admin/admin 首登强制改密(`must_change_password`) |
| `auth_sessions` | 登录会话:只存 token 的 sha256 摘要,30 天过期 |
| `user_degrees` | 九境三阶:用户当前境界(none 表示未入门) |
| `degree_applications` | 学位申请:目标境界、证据链(jsonb)、pending/approved/rejected 与审核人;管理员审核通过时事务内把用户境界提升到目标境界 |
| `plan_schemes` | 学习计划方案:内置 23 个方案(蒙学、小学一年级……研三/硕三,is_builtin=true)与用户自建方案(owner_user_id);按 stage(七档)+ stage_sort/sort_order 排序 |
| `plan_scheme_dimensions` | 方案维度(领域),如「语言与识字」「语文」,挂在方案下按 sort_order 排 |
| `plan_scheme_items` | 方案维度条目:知识内容 + 学习程度,可选关联 knowledge_concepts(SET NULL);内置方案的维度/条目由 024 种子维护 |

### 触发器

`assets_set_updated_at`:每次 `UPDATE` 前把 `updated_at` 设为 `now()`。

## 三、迁移机制

SQL 文件放在 [server/db](../server/db),按文件名排序执行:

```
server/db/
  001_schema.sql                       -- 建扩展、素材表、索引、触发器
  002_seed.sql                         -- 两条示例文本(固定 UUID,不重复插入)
  003_knowledge_schema.sql             -- 知识库建表
  004_knowledge_seed_base.sql          -- 年龄段、学习程度、九类分类
  005_knowledge_seed_language.sql      -- 语领域 seed
  006_knowledge_seed_math.sql          -- 数领域 seed
  007_knowledge_seed_life.sql          -- 生活与安全领域 seed
  008_knowledge_points.sql             -- 按呈现字段展开三档知识点
  009_user_data.sql                    -- 设备、学习设置、计划、学习档案
  010_sage_contributions.sql           -- 智者名与知识贡献表
  011_mengxue_plan.sql                 -- 蒙学年龄档命名与说明更新
  012_knowledge_hierarchy_extensions.sql -- parent_id 子类嵌套、章节、评论、纠错、积分表
  013_knowledge_interaction_indexes.sql  -- 互动查询索引(评论/纠错/积分)
  015_category_naming.sql              -- 九大基类命名与释义更新(古字标记)
  016_unify_category_tree.sql          -- 取消领域层:领域平移为子类,concepts 改挂分类
  017_users_auth_degrees.sql           -- 用户、会话、学位表、学位申请表(登录与权限)
  018_four_degrees.sql                 -- 认知程度扩为四档:入门/熟练/精通/创造
  019_cognitive_levels.sql             -- 知识点认知层级字段(记忆→创新六层,默认记忆)
  020_category_nine_detail.sql         -- 九类细化映射:现代学科按功能面向落为 115 个子分类
  021_seed_six_categories.sql          -- 六类起步知识(12 条概念,九类全有内容)
  022_seed_six_categories_batch2.sql   -- 六类扩灌第二批(24 条概念,铺到初高中/大学档)
  023_seed_foundations_batch2.sql      -- 教养/天地/生命三类加深(9 条概念)
  024_plan_schemes.sql                 -- 学习计划方案:三张表 + 23 个内置方案种子
  025_hardening_indexes.sql            -- 加固:方案 owner 索引、会话过期索引、待审申请唯一索引
  026_rename_domain_columns.sql        -- 旧字段名清理:用户数据表 domain 列改名为 category 口径
```

(无 014,编号跳过;下一个迁移从 027 起。)

执行:

```powershell
cd server
npm run db:migrate
```

脚本行为(见 [src/scripts/migrate.ts](../server/src/scripts/migrate.ts)):

1. 自动创建 `schema_migrations` 表;
2. 读取 `db` 下所有 `.sql`,按文件名升序;
3. 已记录在 `schema_migrations` 里的文件会**跳过**;
4. 每个文件单独开事务,失败回滚,不会留下半成品。

### 新增一次迁移

1. 在 `server/db` 新建文件,编号递增(下一个 027);
2. 内容写成**幂等的**(`CREATE TABLE IF NOT EXISTS`、`ADD COLUMN IF NOT EXISTS` 等);
3. 执行 `npm run db:migrate`。

> 已经执行过的文件不要再改内容——`schema_migrations` 只记文件名,改内容不会重跑。
> 需要调整已有结构时,新开一个编号文件。

## 五、接口与数据库的对应关系

| 接口 | 对数据库的影响 |
| --- | --- |
| `POST /api/assets/text` | 插入一条 `kind = 'text'`,`body` 存正文 |
| `POST /api/assets` | 先上传对象,再插入一条媒体记录;**入库失败会删除已上传的对象** |
| `GET /api/assets/:id/content` | 文本回正文;媒体 302 到预签名地址 |
| `DELETE /api/assets/:id` | 先删对象存储,再删记录 |
| `GET /api/knowledge` | 一次返回年龄段、程度、分类树、概念与分龄内容、章节、sageCredits,只读 |
| `POST /api/knowledge/categories` 等写接口 | 写分类/概念/知识点/章节;**仅管理员**(Bearer token),未登录 401、普通用户 403;表或列缺失时返回 503 `migration_required` |
| `POST .../corrections/review` | **仅管理员**;事务 + `FOR UPDATE` 审核纠错,通过时按服务端定值(5 分)写 `knowledge_point_credits`,并把 `suggested_text` 写回知识点正文(纠错闭环) |
| `GET/POST /api/degree*` | 读写 `user_degrees` 与 `degree_applications`;审核通过在事务内提升境界 |
| `POST /api/auth/login` 等 | `users` 校验密码(scrypt),`auth_sessions` 存 token 摘要 |
| `GET/POST .../comments` 与纠错提交 | 读写评论/纠错表,不要求登录 |
| `GET/POST .../comments` | 读写 `knowledge_point_comments` |
| `POST .../corrections/review` | 事务 + `FOR UPDATE` 审核纠错,通过时写 `knowledge_point_credits` 发积分 |
| `GET/POST/PUT/DELETE .../chapters` | 读写 `knowledge_variant_point_chapters`,删除后重排 position |
| `GET /api/devices/:deviceId/data` | 读取该设备的设置、计划和记录 |
| `PUT /api/devices/:deviceId/data` | 整份替换该设备的数据,写入前自动登记设备;多行 INSERT 分批写入。**注意**:deviceId 是客户端生成的 UUID,接口本身无属主校验(本地优先产品的既定约束),拿到他人 deviceId 即可读写其数据,部署到公网时须自行加鉴权层;单次写入上限 plans 500 条 / records 5000 条(每条正文 ≤5KB) |

对象与知识的读取接口带 `Cache-Control: no-cache` + `ETag`(协商缓存,内容没变回 304;知识写入接口会使缓存失效)。素材接口**读操作匿名开放,上传/删除需要登录**(Bearer token);不接受 SVG 上传(内联展示会变成存储型 XSS)。

对象路径规则:`<kind>/<年>/<月>/<uuid><扩展名>`。

### 应用端只保留框架

| 应用端保留 | 说明 |
| --- | --- |
| 设备 ID | 首次启动生成 UUID,存 `device_id.txt`,用于区分数据库里的用户数据 |
| 最近一次缓存 | `study_cache.json` 存上次成功拉取的整份数据,断网时兜底 |
| 界面与交互 | 知识目录、计划、档案都从 `/api/knowledge` 与设备数据接口读取 |

启动流程:读设备 ID → 未同步修改先 PUT 推回 → 并行拉知识库与设备数据 → 失败但有缓存则离线启动。
删掉缓存文件不会丢业务数据,下一次联网会重新拉取。

## 六、备份与恢复

### 备份

```powershell
docker exec study-postgres pg_dump -Fc -U study study > study.dump
```

### 恢复

```powershell
Get-Content study.dump -Raw -Encoding Byte | docker exec -i study-postgres pg_restore -U study -d study --clean --if-exists
```

## 七、常见问题

### 1. Windows 连不上 5432 / 9000

先看容器状态:

```powershell
npm run db:status
```

容器没起来就 `npm run db:up`;起来了但连不上,看 `docker logs study-postgres`,并确认 Docker Desktop 正在运行、端口未被本机其他进程占用。

### 2. 需要重建整个数据库

```powershell
cd server
docker compose down -v        # 连数据卷一起删,谨慎
docker compose up -d
npm run db:migrate
```

### 3. 换了密码

两处要同步:

1. `docker compose exec study-postgres psql -U study -d study -c "ALTER ROLE study PASSWORD '新密码';"`
2. `server/.env` 的 `DATABASE_URL`(compose 里的 `POSTGRES_PASSWORD` 如要一致也一并改)

### 4. 迁移报 `relation already exists`

说明该文件的变更已经手工执行过,但没被记录。
确认表结构无误后,手动补一条记录即可:

```sql
insert into schema_migrations (filename) values ('012_xxx.sql');
```

### 5. 预签名地址返回 403 SignatureDoesNotMatch

本项目已在 [src/storage.ts](../server/src/storage.ts) 里关闭 flexible checksum 协商
(`requestChecksumCalculation` / `responseChecksumValidation` 设为 `WHEN_REQUIRED`),
如果更换存储实现后再次出现,优先检查这两项。

### 6. 从旧 WSL 环境迁移数据

旧 WSL PostgreSQL 的数据如需保留,先在 WSL 里 `pg_dump -Fc study > study.dump`,
再按上面"恢复"导入 Docker 卷;确认无价值数据则直接 `docker compose up -d` 用新卷跑全量迁移。
