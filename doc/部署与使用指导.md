# 部署与使用指导

面向把「文明重启」在本机或服务器上跑起来的人。按顺序执行即可;每一步的"坑"都写在当步里,最后有完整的故障排查表。数据库细节见 [数据库使用说明.md](数据库使用说明.md),日常开发见 [开发指导文档.md](开发指导文档.md)。

## 一、前置要求

| 组件 | 版本/要求 | 说明 |
| --- | --- | --- |
| Docker Desktop(或 Docker Engine) | 任意近期版本 | Windows 用 Docker Desktop;装好后要能看到 `docker info` 成功 |
| Node.js | ≥ 20 | 服务端运行与迁移 |
| Flutter | 3.47.7 | 客户端构建;CI 固定此版本 |
| 端口 | 3000 / 5432 / 9000 空闲 | 见"坑 2" |

**坑 0:国内网络拉不动 Docker 官方镜像。** MinIO 官方镜像在 Docker Hub 及常见镜像源都会被拒。本项目 `docker-compose.yml` 的对象存储已改用 **SeaweedFS**(`weed server` 一体化模式,S3 端口同为 9000),协议与 MinIO 完全兼容。同时建议配置镜像加速:`~/.docker/daemon.json` 加:

```json
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.m.daocloud.io",
    "https://dockerproxy.net"
  ]
}
```

改完必须重启 Docker Desktop 才生效(用 `docker info` 看 `Registry Mirrors` 是否带上)。若某个镜像仍报 `denied`,换 `docker pull <镜像源>/<仓库>:<tag>` 逐个试,再把能拉到的镜像写进 compose。

## 二、启动依赖服务

```powershell
cd server
docker compose up -d
docker compose ps        # postgres 应显示 (healthy)
```

- 容器:`study-postgres`(PostgreSQL 16,端口 5432)、`study-storage`(SeaweedFS,S3 9000 / 管理页 9333)。
- 数据都在 Docker 卷 `study-server_postgres-data` 与 `study-server_storage-data` 里,`docker compose down` 不删卷;**`down -v` 才会删数据,慎用**。

**坑 1:MinIO 镜像拉不到。** 症状是 `unexpected status 401 Unauthorized` 或各镜像源 `denied`/`not found`。别恋战,直接用 SeaweedFS(项目内已是默认);换回 MinIO 只需改 compose 的镜像与 command,`.env` 凭据对应 `MINIO_ROOT_USER/PASSWORD`。

**坑 2(本项目实测最大的坑):宿主机 5432/9000 被旧服务占用,容器端口绑不上。** 症状很隐蔽——`docker compose ps` 显示 healthy,`/healthz` 也通,但迁移"显示已执行"、容器里 `psql` 却查不到表:因为连接全走到了占用旧端口的老库(本机此前是 WSL 里的 PostgreSQL/SeaweedFS)。排查:

```powershell
docker inspect study-postgres --format "{{json .NetworkSettings.Ports}}"
# 输出里 "5432/tcp":[] 表示没有绑定成功;正常应有 HostPort 5432
```

处理:停掉占用者(本项目: `wsl -d Arch -u root -- systemctl stop postgresql seaweedfs`),再 `docker compose up -d --force-recreate`,重新 `docker inspect` 确认 HostPort 出现,**然后重新执行迁移**。

## 三、配置与迁移

```powershell
copy .env.example .env   # 默认值与 docker-compose.yml 一致
npm install
npm run db:migrate
```

- 迁移按文件名记入 `schema_migrations`,可重复执行;**已执行的文件不要改内容**,新变更新开编号(下一个 021)。
- 想要绝对干净的环境:`docker compose down -v` → `up -d` → `npm run db:migrate`,应从 001 一路执行到最新;若显示"已经执行过"而库明明是新的,基本就是坑 2。

**坑 3:迁移脚本启动会校验全部环境变量**(含 S3 配置)。CI 或脚本环境里只跑迁移时,S3 给占位值即可(`S3_ACCESS_KEY=ci` 等),见 `.github/workflows/server-ci.yml`。

## 四、启动 API

```powershell
npm run dev        # 开发;http://127.0.0.1:3000
# 生产:npm run build && npm start
```

- `/healthz` 同时检查数据库与对象存储,`{"ok":true,"database":"up","storage":"up"}` 才算就绪。
- 启动时会自动创建内置管理员 **admin/admin**(`must_change_password=true`,首次登录强制改密)。

## 五、客户端连接

```powershell
cd app
flutter pub get
flutter run -d windows                       # 本机服务
flutter run -d windows --dart-define=API_BASE_URL=http://192.168.x.x:3000   # 局域网
flutter run -d emulator --dart-define=API_BASE_URL=http://10.0.2.2:3000     # Android 模拟器
```

**坑 4:Android 模拟器里 `127.0.0.1` 指模拟器自己**,必须用 `10.0.2.2` 访问宿主机。真机用局域网 IP,且 Android 9+ 默认禁明文 HTTP——本项目已在 `android/` 配置明文许可(调试用),生产建议上 HTTPS。

**坑 5:客户端有本机缓存兜底。** 断网时用缓存启动、修改记入 `study_cache.json` 待联网推回。所以"改了服务端数据但客户端没变"时,先确认客户端不是在用缓存(看「我的」→ 设置 → 清除缓存,或删文档目录的 `study_cache.json`)。

## 六、一键启动(Windows 开发机)

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-dev.ps1            # 依赖+API+桌面应用
powershell -ExecutionPolicy Bypass -File .\scripts\start-dev.ps1 -ServerOnly
powershell -ExecutionPolicy Bypass -File .\scripts\start-dev.ps1 -Migrate   # 启动前先跑迁移
```

脚本会做 Docker 前置检查(`docker info`)、等 postgres healthcheck、等 9000 端口,再后台起 API 并等 `/healthz`,最后才打开应用。

## 七、账号与权限使用

- **普通用户**:登录后只读,可提交纠错/评论、记录自己的学习数据。
- **管理员(admin)**:可新增/修改分类、知识、知识点、章节,审核纠错,审核学位申请。
- 首次部署后第一件事:**用 admin/admin 登录并修改默认密码**(客户端「我的」→ 设置 → 账号)。生产环境不要保留默认口令。
- 学位(九境三阶):用户在账号弹窗选目标境界提交申请,管理员在同一弹窗的"待审学位申请"区通过/驳回,通过即提升境界。
- 身份与登录态:客户端本机存设备 UUID(`device_id.txt`)与登录会话(`auth_session.json`),token 30 天过期;删除这两个文件即重置本机身份。

## 八、备份与恢复

```powershell
# 备份数据库
docker exec study-postgres pg_dump -Fc -U study study > study.dump

# 恢复(容器里执行)
docker cp study.dump study-postgres:/tmp/study.dump
docker exec study-postgres pg_restore -U study -d study --clean --if-exists /tmp/study.dump
```

对象存储文件在卷 `study-server_storage-data`;客户端侧可用「我的 → 导出档案到本地」留副本,「导入档案副本」恢复(导入前会校验版本与结构,并明确提示覆盖)。

## 九、验证部署是否成功(冒烟清单)

1. `curl http://127.0.0.1:3000/healthz` → ok/database up/storage up。
2. 客户端启动选择年龄档 → 知识库能看到九类与子类树(全新库为九类+各基类子分类)。
3. admin 登录 → 添加一条测试知识 → 客户端知识库出现 → 删除或改名验证写权限。
4. 未登录(或普通用户)确认知识库页面没有编辑入口;直接调写接口应 401/403。
5. 完整回归:`flutter test integration_test/windows_flow_test.dart -d windows`(需服务在跑)。

## 十、故障排查表

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| compose up 报 401 / denied / not found | 镜像源不通或该镜像被拒(如 MinIO) | 配镜像加速并重启 Docker;对象存储用 SeaweedFS |
| `docker info` 失败 | Docker Desktop 没启动 | 启动后等约 1 分钟再试 |
| 迁移"已执行过"但接口 503 / 容器里查不到表 | 坑 2:端口被宿主机旧服务占用,连到了别的库 | `docker inspect` 看端口绑定;停占用者;force-recreate 后重新迁移 |
| `/healthz` 里 storage 不 up | SeaweedFS 未就绪(首次建 volume 稍慢) | `docker logs study-storage`;等 1–2 分钟重启 API |
| 客户端启动显示"加载失败" | API 没起 / 地址不对 | 先 curl /healthz;检查 `--dart-define=API_BASE_URL` |
| 客户端数据"不更新" | 本机缓存兜底中 | 设置 → 清除缓存(有未同步修改时会被拒绝) |
| 登录后仍提示无权限 | token 过期(30 天)或用的是普通用户 | 退出重登;确认角色是 admin |
| 添加计划后服务端没有 | 曾被 me.routes 旧字段校验 400 拦截 | 已修复;若再现,看服务端日志里 PUT /api/devices 的响应码 |
| WSL 提示 localhost 转发中断 | 旧 WSL 环境问题 | 本项目已不依赖 WSL;确保 WSL 里的旧 postgres/seaweedfs 保持停止 |
| 迁移报 relation already exists | 迁移曾手工执行未记录 | 确认结构无误后向 schema_migrations 补一条文件名 |

## 十一、CI 与发布

- `server-ci.yml`:`server/**` 变更时自动起 PostgreSQL 16 服务容器,跑 typecheck + 从零全量迁移 + 测试——CI 绿即代表"新库从零建库"这条路径可用。
- `flutter-ci.yml` / `flutter-release.yml`:Flutter 3.47.7 固定版本;`v*` 标签必须与 `app/pubspec.yaml` 的 `version` 一致。

## 十二、生产部署注意

- API 用 `npm run build && npm start`(或进程管理器);前置 Nginx/Caddy 反代并上 HTTPS。
- 生产环境务必:改掉 admin 默认密码、收紧 `CORS_ORIGIN`(不要 `*`)、给 PostgreSQL/SeaweedFS 设置强口令并限制端口只监听内网。
- 数据库变更永远走新迁移文件;发布顺序:先迁移(向后兼容)→ 再发服务端 → 再发客户端。
